# Fase 11 · a virada — o vetorial virou o padrão de produção

**04/09/2026.** O motor vetorial deixou de ser opção e passou a ser o padrão
global. Este registro é a prova de que a troca funcionou e de que **ela não
alcançou nenhum documento já emitido**.

---

## 1 · Como a virada foi feita

`nr13_motor_pdf = {motor:'vetorial', em:<ISO>}`, gravado pela **RPC oficial de
mutação** (`aplicar_mutacao_storage`, `p_op:'set'`) — a mesma que `salvar()` usa.
Resposta: `{"status":"aplicado","versao":1}`.

Depois de recarregar o app, a chave veio do servidor pela hidratação normal:

```
registroLocal = { motor: "vetorial", em: "2026-09-04T15:23:54.662Z" }   versao 1
```

Nenhuma flag de URL é necessária para o uso normal, e nenhuma foi usada no teste.

## 4 · Rollback

`definirMotorPdf('raster')` continua sendo o caminho, e o mecanismo está intacto:

- o gerador raster **não foi removido** — `html2canvas` e a mensagem
  `"nenhuma folha para gerar"` seguem no bundle de produção;
- `?motor=raster` continua forçando o raster, **provado emitindo** em 04/09
  (`REL-1788503679563`: 522.699 bytes, zero texto extraível, uma imagem por
  página);
- a decisão é coberta por 6 testes unitários em `pdfVetorial.test.ts`.

Ausência de valor continua significando `raster`: apagar a chave já é rollback.
